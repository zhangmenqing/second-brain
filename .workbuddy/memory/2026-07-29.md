# 2026-07-29 工作日志

## 16:13 修复 sync.bat 的 git PATH 问题
- 现象：每小时同步自动化调用 `E:\workbench\sync.bat` 时，bat 内 `git` 命令因子进程 PATH 不含 git 而全部失败（exit 9009），实际从未执行 git 操作。
- 根因：git 是 WorkBuddy 自带 PortableGit（`C:\Users\19712\.workbuddy\vendor\PortableGit\mingw64\bin\git.exe`），不在自动化/cmd 子进程 PATH。
- 修复：在 `sync.bat` 的 `cd /d E:\workbench` 之后加入自动定位 git 并前置 PATH 的逻辑（PortableGit → C:\Program Files\Git\cmd → \Git\bin → x86\Git\bin）。其余 git 调用不变。
- 验证：PowerShell 跑 `sync.bat` 已能正常 commit/pull（日志 `.sync/sync.log` 恢复正常）。
- 残留阻塞：当前 `git push` 失败 exit 128 —— 本地代理 127.0.0.1:7890 离线，github.com 直连不可达。修复提交 `10026b7` 暂未推送（本地 ahead 1），待代理恢复后由下次 hourly 同步自动推送。
- 结论/经验：WorkBuddy 作业环境 bat/cmd 子进程 PATH 不含 git，脚本里动态探测 git 绝对路径更稳妥。
